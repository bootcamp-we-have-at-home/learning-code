Idea 1 — Values have types; variables are labels

JavaScript's primitive types you'll actually meet daily: string, number, boolean, undefined (nothing assigned yet), null (deliberately nothing). Everything else — objects and arrays — is compared by reference: two arrays with the same content are still two different arrays. typeof value asks a value its type.

More examples (optional)

A quick console tour of the corners — predict each before running:

typeof true              // "boolean"
typeof undefined         // "undefined"
typeof (1 + 1)           // "number"    — typeof asks the RESULT, not the expression
typeof []                // "object"    — arrays are objects; use Array.isArray([]) → true
"5" + 5                  // "55"        — + with a string means concatenate
"5" - 5                  // 0           — - only means math, so the string converts

The last two are why type-aware comparison matters so much in lesson 1-10: operators quietly convert types, and === is how you opt out of the guessing.

Idea 2 — const by default

Modern JS declares with const unless reassignment is genuinely needed, then let. You will still see var in older curriculum snippets — it's the legacy form with looser scoping; don't write new code with it. Note the nuance the console showed you: const stops reassignment of the label, not mutation of the object it points to — const arr = []; arr.push(1) is legal.

More examples (optional)

Where the line between reassignment and mutation actually falls:

const user = { name: "Amjad" }
user.name = "Amjad S."     // fine       — mutating the object the label points to
user = { name: "Other" }   // TypeError  — re-pointing the label itself

let count = 0
count = count + 1          // fine       — let exists exactly for labels that move

const wins = 0
wins = wins + 1            // TypeError  — and that error is USEFUL: it tells you
                           // this value was never meant to change

Practical rule: write const, and let the error upgrade it to let only when reassignment is truly the design — most variables never are.

Do it for real (~15 min)

In the console:

  1. Declare a constant, then try to reassign it: 
    const profile = "your name"
profile = "other"       // TypeError: a const cannot be reassigned
    You should see a TypeError naming the constant.
  2. Run: 
    const skills = ["html", "css"]
skills.push("git")      // mutate the array through a const label
skills                    // ["html", "css", "git"]
    You should see all three items — mutation through a const label works.
  3. Run: 
    typeof null              // "object"
    You should see "object" — a famous historical bug kept for compatibility; recognize it so it never confuses you.

1-10 — Objects, Operators & the DOM

~60 minutes · Week 1, Day 4 · Source: curriculum Day 4 (JavaScript objects, comparison & logical operators, DOM morning challenge)

Why this matters: objects are how every API this course touches represents data; the operators decide every if; and the DOM exercise reconnects your freeCodeCamp knowledge to the profile page you actually own.

Idea 1 — Objects: labeled data

const project = {
  name: "Profile page",
  tech: ["html", "css"],
  finished: false,
  describe() { return `${this.name} (${this.tech.join(", ")})`; },
};

project.name          // "Profile page"   — dot access
project["name"]       // same, bracket access — needed when the key is in a variable
project.describe()    // "Profile page (html, css)"

(The backtick string in describe() is a template literal, and join(", ") is an array method 1-8 didn't cover: it glues the array's items into one string with the separator between them — ["html","css"].join(", ") → "html, css".)

More examples (optional)

Objects nest, and arrays of objects are how every API you'll ever call sends data:

const student = {
  name: "Amjad",
  contact: { github: "amjad-codes", city: "Gaza" },   // an object inside an object
}
student.contact.github        // "amjad-codes" — chain the dots level by level

const projects = [
  { name: "Profile page", done: true },
  { name: "Quiz app",     done: false },
]
projects[0].name                             // "Profile page" — index in, then dot
projects.map(p => p.name)                    // ["Profile page", "Quiz app"] — 1-8 meets objects
projects.filter(p => !p.done).length         // 1 — how many are still open?

Bracket access earns its keep when the key lives in a variable: const field = "name"; student[field] works, student.field looks for a key literally called field.

Idea 2 — Comparisons that don't lie

Always compare with === / !== (no type conversion). The loose forms == / != convert types before comparing ("5" == 5 is true) — a classic bug source you'll see in older code but shouldn't write. Logical operators: && (both), || (either), ! (not) — and they return operands, not booleans, which is why name || "anonymous" works as a fallback.

More examples (optional)

The whole falsy list — six values; everything else is truthy:

false   0   ""   null   undefined   NaN            // the complete falsy family

Boolean("0")        // true  — a non-empty string, even "0"
Boolean([])         // true  — an empty array is still an object
5 > 3 && "ok"       // "ok"  — && returns the last operand when all are truthy
null || 0 || "hi"   // "hi"  — || returns the first truthy operand it meets

And the comparison traps worth seeing once, so === feels earned:

"10" > "9"          // false — two strings compare alphabetically: "1" < "9"
"10" > 9            // true  — mixed types: the string converts to a number
null == undefined   // true  — loose equality's special case
null === undefined  // false — strict says: different types, done

Part A — console (~15 min). The F12 console from lesson 1-1, as in 1-7 and 1-8.

  1. Build a me object — same shape as the project example in Idea 1 — with your name, a skills array, and a yearsOfCS number:

  name: "your name",
  skills: ["html", "css"],

me.skills.length        // the count you expect
    Check: me.skills.length returns the count you expect.
  2. Predict then run:

"5" == 5

    Success check: false, true, "fallback", "" — and you can explain each.

Part B — DOM challenge on your page (~20 min). The curriculum's Day 4 sets a DOM manipulation challenge; here it targets your own page. The four DOM calls below are freeCodeCamp material — they're also in the JavaScript cheat sheet's DOM section; skim it now if they feel far away. Open ~/code/week-1/index.html in the browser, work in the console first, then make it permanent.

  1. Grab your heading and read its text: 
    const h1 = document.querySelector("h1")
h1.textContent              // your name
    You should see your name.
  2. In the console, add a live skill counter: 
    const skills = ["html", "css", "flexbox", "git"];
const p = document.createElement("p");
p.textContent = `Currently practicing ${skills.length} skills: ${skills.join(", ")}`;
document.querySelector("#about").append(p);
    You should see the paragraph appear in your About section. Refresh — it's gone: console changes aren't saved.
  3. Make it permanent: in a terminal, type: 
    cd ~/code/week-1
git switch -c add-skill-counter
    (the repo you published in 1-6). Then in your editor — open the ~/code/week-1 folder again if it still shows workflow-practice from 1-9 — put the same code in a <script> tag just before </body>. Save, refresh. You should see it survive reloads now.
  4. Commit, push, open a PR, merge, and sync — the full 1-5 loop, from memory, in the same terminal (still in ~/code/week-1). Use the commands you learned in 1-5. Success check: the PR shows exactly one changed file, and after syncing, git branch lists only main.

Check yourself — predict the output

const user = { name: "", city: "Gaza" };
console.log(user.name || "anonymous");
console.log(user.name === undefined);
Reveal

"anonymous" — empty string is falsy, so || falls through. Then false — name exists and is "", which is not undefined. (A key that's truly absent, like user.email, would give undefined.)

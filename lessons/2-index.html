Week 2 — Testing, Functions & TDD

Curriculum source: coursebook/week-2 · ~20 hours including the project

What this week leaves you with

From the curriculum's learning outcomes: what testing is and why we do it, unit vs integration tests, the TDD methodology and its red–green–refactor cycle, setting up and using npm and Jest, why pure functions are easy to test, what callbacks are and how to use them, and how to ping-pong code in pairs (adapted here to ping-pong with the agent). The week ends with a tested, pure-function, localStorage-backed ecommerce app (project brief). Week 3 (APIs and async) assumes all of that is muscle memory — it opens by asking "what is a callback and why would you use one?" and moves straight into asynchronous and parallel functions, which is why 2-1, 2-7 and 2-9 are the load-bearing lessons of this week.

Prerequisites

  • Week 1, lessons 1-1 to 1-11. Specifically: the terminal (1-4 — cd, ls, mkdir, the safety ritual, the ~/code/ workspace convention), git and GitHub including git clone (1-5 — workshops this week clone repos), JS values and const/let (1-7), array methods with arrow functions passed as arguments (1-8 — those arrows were callbacks, and 2-1 says so out loud), objects, === and template literals (1-10).
  • Soft prerequisite: lesson 1-9 Git Conflicts was added after the first pass through week 1. The week-2 project merges a PR per user story, but you are its only committer and each branch merges before the next starts — so no conflicting merge is expected, and 1-9 is not a blocker. Still, do 1-9 as catch-up before the week-2 project if you haven't run it yet.
  • Not required in advance: Node.js and npm. Week 1 never installed them; lesson 2-2 checks for Node and installs it before anything else this week needs it. Do not install ahead of time — 2-2 wants to see the "not found" case.
  • Same machine setup as week 1: browser, editor (VS Code recommended, autosave off — save before you run, stage or refresh), git, GitHub account.

Sequencing notes

Deviations from the week-2 schedule order, with reasons — the scream register:

  1. SPLIT, in place: "Intro to Functions" is one slide deck scheduled twice (Day 1 09:00 and Day 2 10:30). Rather than merge the two sittings into one lesson, it splits along the deck's own halves: 2-1 takes the first half (function anatomy, first-class functions, callbacks, higher-order functions) in the Day 1 slot; 2-7 takes the second half (funception, the call stack, nested callbacks, sync vs async, setTimeout) in the Day 2 slot. Merging would put roughly fourteen new items into a single lesson, violating STYLE.md rule 2. 2-7 is also the one lesson in the track with three idea sections rather than the skeleton's 1–2: the deck's second half is genuinely three concepts (funception/nesting, the call stack, sync vs async + the event loop), and splitting it a third time would strand the event-loop video from the code that assumes it. Each section still carries its own collapsed examples block and read-more line.
  2. MOVED EARLIER: the event-loop video (Day 2, 16:00 — scheduled after the pure-functions workshop) is folded into 2-7, in the Day 2 10:30 slot. The functions deck's async half explicitly assumes the video has already been watched, and a solo learner gains nothing from the cohort's split viewing time.
  3. MOVED LATER: "Intro To Project" (Day 2, 16:30) becomes the opening of the project lesson 2-10, after Day 3's traffic-lights challenge. Solo, there is no cohort logistics reason to preview the brief a day before starting it, and nothing in the Day 3 morning challenge depends on having seen it.
  4. COMPRESSED: the ES6 morning challenge (Day 2, 09:00) becomes a refresh-with-skip-checkpoint lesson, following the 1-7 pattern. Week 1 already taught const/let (1-7), arrow functions (1-8) and template literals (1-10); the checkpoint probes all nine features, and the body teaches only the genuinely new ones — default parameters, spread, destructuring, Set, class — plus their ES5 equivalents, which the challenge itself requires.
  5. ADAPTED: Day 5's cohort events (code review, respond to issues, presentations) fold into 2-10's closing phase: the agent reviews the project as your pair following the etiquette in codereviewintro.md, you respond to the review issues, and the presentation becomes a solo README/demo writeup.
  6. NO SLOT IN SCHEDULE: the week's research topics have no scheduled session, so they are distributed as pointers instead — unit vs integration vs e2e and the testing-framework comparisons from 2-3, test coverage / Istanbul / nyc from 2-4, and web storage taught for real inside 2-10, because the project's localStorage requirement makes it required material (STYLE.md rule 4), not optional research.
  7. DROPPED: Day 3's Computer Science Session (no linked content) and the Day 5 PM External Workshops — both cohort-only; see "Not applicable solo" above.

How feedback works this week

Every lesson footer asks two questions (followability 1–5, stuck-points); tell your answers to your teacher (the agent), which records them in feedback/week-2.md. A score ≤3 or any stuck-point rewrites the lesson before the next student sees it.

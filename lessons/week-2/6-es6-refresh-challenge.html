2-6 — ES6 Features Refresh & the ES6→ES5 Challenge

~60 minutes (15 reading + 45 challenge) · Week 2, Day 2, 09:00–10:30 morning challenge · Source: curriculum bootcamp-we-have-at-home/mc-es6-challenge, part 1

Why this matters: Half the JavaScript you'll read this year is ES5 and half is ES6.

Translating between them by hand is the fastest way to stop guessing what the newer syntax actually does.

Spread and destructuring in particular come back in the week project (2-10) and in week 3's API work.

Checkpoint — try to skip the reading

`sum: ${1 + 1}`

[...[1, 2], ...[3]]

new Set([1, 1, 2]).size
class T { constructor(n) { this.n = n } } ; new T(5).n
Reveal expected results

[1, 2]                   // const blocks reassignment, not mutation
[2, 4, 6]                // arrow function passed to map (1-8)

Idea 1 — Nine ES6 features and their ES5 undo

You have been writing ES6 since week 1 without the label: every const, every arrow you passed to map, every backtick string.

Three of the nine features below are exactly those. One row each, then move on:

FeatureTaught inES5 equivalent
let / const1-7 (const-by-default, var as legacy)var — looser scoping, see Idea 2
arrow functions1-8 (the arrows you passed to map)function (x) { return … }
template literals1-10 (the backtick string in describe())"a " + b + " c" concatenation

The other six are new here.

Each one below is a code block plus its ES5 undo — the older way of writing the same thing:

Default parameter values — a value used when the argument is undefined:

const greet = (message = "HI THERE") => message;   // ES6
greet()               // "HI THERE"
greet("Morning")      // "Morning"

function greet(message) {                          // ES5 undo
  if (message === undefined) message = "HI THERE"; // check-and-assign, first line of the body
  return message;
}

Spread (... in a value position) — pours an array's elements out into a new array or an argument list:

const a = [1, 2], b = [3];
[...a, ...b]          // [1, 2, 3]         — a new array, originals untouched
Math.max(...a)        // 2                 — elements become arguments

a.concat(b)           // ES5 undo for the array case — same [1, 2, 3]
Math.max.apply(null, a)  // ES5 undo for the arguments case

Rest (the same ..., but in a binding position) — collects the leftovers instead of spreading them.

Same three dots, opposite direction. You saw it in the checkpoint as const [a, ...rest] = [1, 2, 3].

Destructuring — pull keys or positions straight out into variables:

const config = { expected: 1, actual: 2 };
const { expected, actual } = config;      // ES6 object destructuring
const [first, second] = [10, 20];         // ES6 array destructuring — by position

var expected = config.expected;           // ES5 undo: one manual assignment per name
var actual = config.actual;

Set — an object like an array, except every value appears at most once:

const s = new Set([1, 1, 2]);
s.size                                    // 2
s.forEach(v => console.log(v))            // 1 then 2 — Sets have forEach like arrays

[1, 1, 2].filter(function (v, i, all) {   // ES5 undo: [1, 2] — note the ES5 undo uses
  return all.indexOf(v) === i;            // a function expression, not an arrow:
});                                       // keep a value only at its FIRST index

class — a syntax sugar layer over the constructor function + prototype pattern JavaScript always had.

The one thing to notice: nothing new was added to the language. Both versions below build the same object.

class Test {                              // ES6
  constructor(name) { this.name = name; }
  run() { return this.name; }
}

function Test(name) { this.name = name; } // ES5 undo — the constructor
Test.prototype.run = function () {        // methods hang off the prototype
  return this.name;
};
new Test("a").run()                       // "a" — identical either way
More examples (optional)

Destructuring earns its keep hardest in parameter lists — the exact shape you'll meet in the challenge file:

const show = ({ name, city = "unknown" }) => `${name} — ${city}`;   // destructure + default
show({ name: "Amjad" })                    // "Amjad — unknown"

function show(user) {                      // ES5 undo: unpack manually, then default
  var name = user.name;
  var city = user.city;
  if (city === undefined) city = "unknown";
  return name + " — " + city;
}

Spread also copies objects (ES2018), which is how the 2-10 project will make a changed copy of a cart item without mutating the original:

const item = { id: 1, qty: 1 };
const bumped = { ...item, qty: 2 };        // { id: 1, qty: 2 } — item is untouched
item.qty                                   // 1

And the classic Set one-liner you will see everywhere — deduplicate an array:

[...new Set(["a", "b", "a"])]              // ["a", "b"] — Set removes, spread re-flattens

Read more: javascript.info — destructuring assignment · MDN — Set · javascript.info — classes and what they desugar to

Idea 2 — Reading ES5 without flinching

Idea 1 gave you the undo for each feature one at a time. The challenge asks you to write a whole file in that older dialect on purpose.

Four things to have straight before you do.

var is function-scoped, not block-scoped. Lesson 1-7 called it "the legacy form with looser scoping". This is what that means in practice.

A var inside an if or a for leaks to the whole surrounding function. Re-declaring it silently reuses the same binding.

let greeting = "say Hi";
if (true) { let greeting = "say Hello"; }
greeting                       // "say Hi"    — the inner let was its own variable

var greeting = "say Hi";
if (true) { var greeting = "say Hello"; }
greeting                       // "say Hello" — same variable, overwritten

So let → var is a safe swap only when no block re-declares the same name.

That is true almost everywhere — and famously untrue inside loops that create functions (see the collapsed examples below).

String concatenation replaces template literals: `Expected ${a}, found ${b}` becomes "Expected " + a + ", found " + b.

Mind the spaces. They move inside the quotes, and losing one is the most common way to break output in this challenge.

.concat() is the array-joining method spread replaced: a.concat(b) returns a new array with b's items appended, leaving both originals alone (a transformer, in 1-8's vocabulary).

Constructor functions + prototype are what class compiles to, shown above.

Read Thing.prototype.method = function () {…} as "every object made by new Thing(…) can call .method()".

More examples (optional)

The loop case, because it's the one that actually bites — the curriculum's bonus question asks exactly this:

for (let i = 0; i < 3; i++) setTimeout(() => console.log(i));   // 0 1 2
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));   // 3 3 3

let makes a fresh i per iteration; var makes one i for the whole function, and by the time the callbacks run it is 3. (Why the callbacks run after the loop finishes at all is 2-7's subject — park it for now.)

Arrow functions are not always a drop-in for function either: an arrow takes this from the surrounding scope, a function gets its own. It doesn't bite in this challenge's file — none of the arrows there use this — but it is the reason "replace all arrows with functions" is not a blind find-and-replace in general.

Read more: javascript.info — the old var · MDN — Array.concat · the ES6↔ES5 table in the JavaScript cheat sheet

Do it for real (~45 min) — ship it for Internet Explorer

The curriculum's scenario: as part of a job application you wrote an assertEquals function using every ES6 feature you could.

An hour before the deadline you re-read the brief — it must run in Internet Explorer, which supports none of it.

Your job: replace as many ES6 features as possible with ES5 without changing a single character of the program's output.

The repo is explicit that this is not a race: a variety of different features attempted beats complete coverage of one.

Timebox it at 45 minutes and stop where you stop.

  1. Confirm Node is there (installed in lesson 2-2) and go to your code folder: 
    node -v          # v20 or v22 — if this errors, do 2-2 first
cd ~/code        # the workspace folder from 1-4
    You should see a version number, and no error from cd.
  2. Clone the challenge repo (git clone from lesson 1-5) and step into it: 
    git clone https://github.com/bootcamp-we-have-at-home/mc-es6-challenge.git
cd mc-es6-challenge
ls ES6-ES5       # README.md  assertEquals.js
    You should see both files listed.
  3. Run the program before touching it — this output is the contract you must not break: 
    node ES6-ES5/assertEquals.js
    You should see exactly these six lines: 
    Comparing an object with an additional key: Found .b, none expected
Comparing an object missing a key: Expected .a, but was not found
Comparing different types: Expected type number, but found type null
Comparing objects with different values: Expected .a 5, but found 6
Comparing arrays of different lengths: Expected array length 3, but found 4
Comparing nested objects: Expected .a.b 5, but found 6
    Those lines are the six deliberately-failing assertions being reported — the program is working correctly.
  4. Freeze that output into a file so you can compare against it after every edit. Safety: > overwrites its target silently, so check the name is free first: 
    ls baseline.txt                              # "No such file or directory" = safe to write
node ES6-ES5/assertEquals.js > baseline.txt  # capture the six lines
cat baseline.txt                             # verify they landed
    You should see the same six lines inside baseline.txt.
  5. Learn the one-command safety net you'll use after every conversion. diff compares two files and prints only the differences; - means "the second file is whatever is being piped in": 
    node ES6-ES5/assertEquals.js | diff baseline.txt -   # silence = identical output
    You should see no output at all. Silence is the pass. Any < / > lines mean you changed behavior — undo the last edit and look again.
  6. Open the working folder in your editor: File → Open Folder → ~/code/mc-es6-challenge (it probably still shows a week-1 folder), then open ES6-ES5/assertEquals.js. Read it top to bottom once — it's about 100 lines and the comments above each feature tell you what to replace. Autosave is off: save the file before every re-run, or you'll be testing the old version. You should see comments like // Replace default parameter values sitting above the lines they describe.
  7. Easiest first — const and let → var, everywhere in the file. Save, then: 
    node ES6-ES5/assertEquals.js | diff baseline.txt -
    Check: silence. (Idea 2's loop example is the case where this swap would break — there is no such loop here.)
  8. Arrow functions → function expressions. Convert one, re-run, then the next — small steps make a broken diff easy to attribute: 
    var getType = function (x) { … };            // was: const getType = x => { … }
var buildTrace = function (element, key) {   // was a one-line arrow: add an explicit return
  return element instanceof Array ? "[" + key + "]" : "." + key;
};
    Check: silence after each save. Remember a body-less arrow returns its expression; a function needs the word return.
  9. Template literals → concatenation, one throw at a time: 
    throw new Error("Found " + trace + ", none expected");   // was: `Found ${trace}, none expected`
    Check: silence — and if diff shows a line missing a space, that's the space that used to live inside the backticks.
  10. The default parameter on deepEquals — drop trace='' from the parameter list and restore it in the body: 
    function deepEquals(a, b, trace) {
  if (trace === undefined) trace = '';
  …
    Check: silence. Get this one wrong and the traces come out as undefined.a — the diff will show you immediately.
  11. Now the harder three, in the repo's order — spread, then Set, then class. All three live in these two places: 
    new Set([...Object.keys(a), ...Object.keys(b)]).forEach(…)   // spread + Set
class Test { constructor({expected, actual, description}) … } // class + destructuring
    Use the ES5 undos from Idea 1: .concat() for the spread, the filter-by-first-index idiom for the Set (written as a function expression, not an arrow — an arrow here would put the ES6 straight back), a constructor function with Test.prototype.run = function () {…} for the class, and manual config.expected assignments for the destructuring. Check: silence after each one. Anything that stays silent is done; anything you don't reach is fine — variety beats completeness here.
  12. Stop at 45 minutes wherever you are, and take stock: 
    node ES6-ES5/assertEquals.js | diff baseline.txt -   # final confirmation: silence
grep -nE "=>|const |let |\`|\.\.\.|class |new Set|\{ *[a-z]+ *(, *[a-z]+ *)*\}" ES6-ES5/assertEquals.js
# covers all nine: arrows, const/let, template literals, spread/rest,
# class, Set, and destructuring patterns. Read the remaining default
# parameters by eye — an = inside a parameter list is the tell.
    Success check: the diff is silent and you can name each remaining ES6 construct grep found and say what its ES5 form would be — that, not a fully converted file, is the outcome this challenge is graded on.

Check yourself — predict the output

Someone converted this ES6 function to ES5. Predict what each version prints for label({ id: 7 }):

const label = ({ id, tag = "item" }) => `${tag}-${id}`;      // ES6

function label(opts) {                                       // their ES5 attempt
  var id = opts.id;
  var tag = opts.tag;
  return tag + "-" + id;
}
Reveal

ES6: "item-7". Their ES5: "undefined-7" — they translated the destructuring but dropped the default value. The fix is the check-and-assign from Idea 1: if (tag === undefined) tag = "item"; before the return. This is exactly the class of bug the diff safety net catches in step 5.

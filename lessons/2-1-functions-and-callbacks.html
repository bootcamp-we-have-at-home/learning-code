2-1 — Functions, First-Class: Callbacks & Higher-Order Functions

~45 minutes · Week 2, Day 1, 09:00–11:00 (session 1 of 2) · Source: curriculum intro-to-functions-slides.md, first half

Why this matters: everything week 2 tests is a function, and everything week 3 does with APIs is "here's a function, run it when the data arrives".

Today you name the thing you already did in lesson 1-8: the arrow you handed to map was a callback.

Idea 1 — Anatomy refresh: calling vs referencing, return vs side effect

You've written functions in freeCodeCamp's JavaScript section and used them in lessons 1-7 and 1-8. So this section is a refresh, not new material.

A function has a name, parameters, and a body.

The values you hand it when you call it are its arguments:

const myFunction = (argument1, argument2) => {
  console.log("first argument:", argument1);    // a side effect — it prints
  console.log("second argument:", argument2);   // still no return statement
};

myFunction("hello", "world")   // prints both lines, then evaluates to undefined
The coursebook writes function myFunction(a, b) { … }; today we write const myFunction = (a, b) => { … } — same behavior here, less noise. Both forms appear in code you read. (Arrow syntax is freeCodeCamp material, introduced in 1-8 — javascript.info's two-minute refresher if it's rusty.)

Three distinctions do all the work today:

  • Side effect vs return value. console.log is a side effect: something happened in the world (text on screen), but the function handed nothing back. A return hands a value back to whoever called it.
  • Every function returns something. With no return statement, the function returns undefined. That's not an error — it's the default.
  • Calling vs referencing. myFunction() — with parentheses — runs it and evaluates to its return value. myFunction — no parentheses — is the function itself, the value, unrun. That one pair of parentheses is the whole lesson.
More examples (optional)

What each expression evaluates to, when double returns and shout only prints:

const double = (n) => n * 2;              // implicit return: no braces, no return keyword
const shout  = (word) => { console.log(word.toUpperCase()); };   // side effect only

double(4)              // 8            — the returned value
double                 // (n) => n * 2 — the function itself, not run
shout("hi")            // prints HI, then evaluates to undefined
const x = shout("hi")  // prints HI; x is undefined — nothing was returned
double(4) + 1          // 9            — you can do maths with a return value
shout("hi") + 1        // NaN          — undefined + 1; the classic "forgot to return" bug

And the arrow shorthand: (n) => n * 2 is exactly (n) => { return n * 2; }. The braces buy you multiple statements; the price is writing return yourself.

Idea 2 — Functions are first-class values

In lesson 1-8 you handed an arrow function straight to map, the way you'd hand it a number or a string. That worked on purpose.

In JavaScript a function is a first-class value.

Anywhere you can put a number, you can put a function.

Below are five places it can go. You already know four of the containers — variables, objects (1-10), arrays (1-8), and arguments:

// 1 — in a variable
const sayHi = () => console.log("Hello world");
const alias = sayHi;        // note: NO parentheses — copying the function, not its result
alias();                    // "Hello world"

// 2 — in an object, where a function-valued property is called a METHOD (1-10)
const doggo = {
  name: "Mackerel",
  bark: () => console.log("woof!"),
};
doggo.bark();               // "woof!"     — with parens, it runs
doggo.bark;                 // the function itself — no bark

// 3 — in an array, reached by index like any element (1-8)
const actions = [() => console.log("first"), () => console.log("second")];
actions[1]();               // "second"    — index in, THEN call

// 4 — as an argument to another function
const run = (fun) => fun();
run(sayHi);                 // "Hello world" — pass sayHi, let run decide when to call it

// 5 — as the RETURN VALUE of another function
const greetSomeone = (greeting) => (name) => console.log(greeting, name);
const sayHello = greetSomeone("hello");   // sayHello is now a function
sayHello("world");                        // "hello world"
The coursebook writes #5 as function greetSomeone(greeting) { return function (name) {…} }; the arrow version above returns the inner arrow implicitly. Same thing, and the inner function remembers the greeting it was born with.

Two words name what you just read, and the slide deck flags both with a JARGON ALERT.

They are also the vocabulary of week 3:

  • A function passed as an argument to another function is a callback function. In #4, sayHi is the callback.
  • A function that takes a function as an argument and/or returns one is a higher-order function. In #4, run is higher-order; in #5, greetSomeone is too.

Which makes lesson 1-8 retroactively make sense.

The arrow you passed to map was a callback, and map is a higher-order function.

nums.map(n => n * 2) hands map a function and lets map call it once per element.

Same for filter, find and forEach — you have been writing callbacks for a week without the word.

More examples (optional)

Callbacks stop looking academic the moment the caller decides when to run them:

// A higher-order function you could write today: run something twice
const twice = (fn) => { fn(); fn(); };
twice(() => console.log("ping"));      // "ping" "ping" — an ANONYMOUS callback, defined inline

// The DOM version from 1-10 — the browser calls your function when the click happens
document.querySelector("h1")
  .addEventListener("click", () => console.log("clicked!"));

// A returned function that pre-loads an argument (same shape as greetSomeone)
const multiplyBy = (factor) => (n) => n * factor;
const triple = multiplyBy(3);
triple(5);         // 15
[1, 2, 3].map(triple);  // [3, 6, 9] — a returned function, used as a callback
// (the semicolons matter here: a line starting with [ continues the line above it)

Note addEventListener("click", fn): you never call fn yourself. You hand it over and the browser calls it later — the exact pattern week 3 uses for network responses.

Do it for real (~20 min)

The deck's own sequence, rebuilt in the browser console — F12 → Console, from lesson 1-1, as in 1-7, 1-8 and 1-10. No files, no folders today.

Predict the output before you press Enter on every step. The prediction is the exercise; the typing is just bookkeeping.

  1. Define the deck's function and call it: 
    const myFunction = (a, b) => { console.log("first:", a); console.log("second:", b); }
myFunction("hello", "world")
    You should see two printed lines, then undefined in a different colour — that last line is the return value, and there's no return, so it's undefined.
  2. Give it something to return: 
    const myReturner = (a, b) => { console.log("first:", a); return 0; }
myReturner("hello", "world")
    Check: one printed line, then 0. The print is the side effect; the 0 is the output.
  3. Calling vs referencing — the difference in one screen: 
    myFunction("a", "b")   // runs it:  prints, then undefined
myFunction             // the function VALUE itself: prints nothing
    You should see the second line echo the function's source code back at you, with nothing printed.
  4. Store it in a variable and in an object (the object shape is from 1-10): 
    const alias = myFunction          // no parens — copying the function
alias("via", "alias")             // prints, exactly as myFunction would

const doggo = { name: "Mackerel", bark: () => console.log("woof!") }
doggo.bark()                      // "woof!"
doggo.bark                        // the function itself — nothing printed
    Success check: alias("via", "alias") prints the same two lines, and only doggo.bark() barks.
  5. Store one in an array and call it by index (zero-indexed, as in 1-8): 
    const mixed = [0, 1, 2, 3, 4, () => console.log("hello from index 5!")]
mixed[5]                          // the function value
mixed[5]()                        // runs it
    You should see hello from index 5! only on the last line.
  6. Pass a function as an argument — your first hand-written higher-order function: 
    const foo = (fun) => { fun(); }
foo(myFunction)                   // myFunction runs INSIDE foo, with no arguments
    You should see first: undefined and second: undefined — foo called it without passing anything along.
  7. Two ways to break it, on purpose — run them one line at a time (pasted together, the first throw stops the second line from running), and predict each error before pressing Enter: 
    foo("a string")                   // TypeError: fun is not a function
foo(myFunction())                 // prints first, THEN the same TypeError
    Success check: both raise TypeError: fun is not a function. On the second, myFunction() ran before foo did and handed foo its return value, undefined — and undefined() is not callable. That is the whole trap: foo(myFunction) passes the function, foo(myFunction()) passes its result.
  8. Pass an anonymous function instead — no name, defined at the point of use, exactly like the arrows in 1-8: 
    foo(() => console.log("hello anon"))
    Check: hello anon.
  9. Return a function from a function — the deck's greetSomeone: 
    const greetSomeone = (greeting) => (name) => console.log(greeting, name)
greetSomeone("hello")             // a FUNCTION, not a greeting
const sayHello = greetSomeone("hello")
sayHello("world")                 // "hello world"
sayHello("Amjad")                 // "hello Amjad" — the greeting stuck
    Success check: greetSomeone("hello") alone prints nothing and echoes a function; sayHello greets everyone you pass it with "hello". You just built a function factory.
  10. Say the words out loud, pointing at your own console history: in step 6, which value was the callback and which function was higher-order? Then find the same two roles in [1, 2, 3].map(n => n * 2). 
    [1, 2, 3].map(n => n * 2)         // callback: n => n * 2   ·   higher-order: map
    Check: in step 6 the callback is myFunction and the higher-order function is foo — same shape, different names.

Check yourself — predict the output

Given these two definitions, what does each of the last two lines do?

const myFunction = () => { console.log("Hello world"); return 0; };
const foo = (fun) => { fun(); };

foo(myFunction);
foo(myFunction());
Reveal

foo(myFunction) → prints Hello world once. The function itself was passed in; foo called it. (foo ignores the returned 0, and foo itself returns undefined — it has no return.)

foo(myFunction()) → prints Hello world once, then throws TypeError: fun is not a function. The parentheses ran myFunction first; its return value 0 was passed to foo; foo tried 0(). This is the deck's own "Oops!" moment — and it's the same mistake as writing button.addEventListener("click", handleClick()).

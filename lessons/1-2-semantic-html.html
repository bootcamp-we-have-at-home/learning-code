1-2 — Semantic HTML & Accessibility

~60 minutes · Week 1, Day 1 · Editor and browser only — no terminal, no git yet

Why this matters: the profile page you start here grows into your portfolio project at the end of this week. Semantic HTML is also a favorite interview topic.

Idea 1 — Tags that say what they mean

freeCodeCamp's Responsive Web Design section (your prerequisite) taught you the tags; the professional habit is choosing them for meaning. <div class="header"> and <header> look identical on screen — but only the second one is announced as a landmark by a screen reader, understood by search engines, and instantly legible to the next developer.

The skeleton to internalize — six tags plus one rule:

<header>   who/what this page is; usually contains <nav>
<nav>      the page's main navigation links
<main>     the unique content — exactly ONE per page
<section>  a thematic grouping inside main
<article>  self-contained content that would make sense alone
<footer>   closing info: copyright, contact, small links

<aside> (tangential content, e.g. a sidebar) exists too — it's on the cheat sheet; look it up when you need it, don't memorize it now.

More examples (optional)

The same news-article page, before and after the semantic habit:

<!-- div soup: renders identically, means nothing -->
<div class="top">
  <div class="menu">…links…</div>
</div>
<div class="content">
  <div class="story">
    <h2>Storm hits the coast</h2>
    <p>…</p>
  </div>
</div>
<div class="bottom">© 2026</div>
<!-- semantic: a screen reader can jump straight to main or nav -->
<header>
  <nav>…links…</nav>
</header>
<main>
  <article>                     <!-- would make sense on its own → article -->
    <h2>Storm hits the coast</h2>
    <p>…</p>
  </article>
</main>
<footer>© 2026</footer>

Choosing between <section> and <article>: could you syndicate the block alone in an RSS feed and have it still make sense? Yes → article (a news story, a product card). No, it only groups things thematically → section (the "Projects" area of your profile).

Idea 2 — Accessibility is checkable, not vibes

Semantic structure is the first half of accessibility. The second half is verifying it: browsers ship an auditor called Lighthouse that scores your page and lists concrete fixes. You'll run it on your own page in a few minutes.

More examples (optional)

The three findings Lighthouse raises most often on beginner pages, and what each means for a real person:

  1. "Image elements do not have alt attributes" — a screen-reader user hears "image" and nothing else. Fix: <img src="me.jpg" alt="Portrait of Amjad at his desk">; purely decorative images get an empty alt="" so they're skipped silently.
  2. "Background and foreground colors do not have sufficient contrast" — light-grey-on-white text that low-vision users (and anyone in sunlight) can't read. Fix: darker text or lighter background until the ratio passes.
  3. "<html> element does not have a lang attribute" — the screen reader doesn't know which language's pronunciation to use. Your base document from step 3 already has lang="en"; a page in Arabic would declare lang="ar".

Read more: W3C — what accessibility is and who it serves · WebAIM contrast checker (paste two colors, get a pass/fail)

Do it for real (~35 min)

All in your editor and browser. (If you don't have an editor yet, install VS Code first — ask your teacher for help.)

  1. In your file manager or editor, create the folder ~/code/week-1 (a code folder in your home folder, with week-1 inside). You'll reuse it all week. Success check: in VS Code, File → Open Folder shows week-1 empty and open.
  2. Create a new file in it named index.html. You should see the file appear in the editor's sidebar.
  3. Type (don't paste) the base document: 
    <!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>My profile</title>
</head>
<body>

</body>
</html>
    Success check: save the file, then open it in your browser (double-click it, or drag it onto a browser window). You see an empty page whose tab reads "My profile".
  4. Inside <body>, add a <header> containing an <h1> with your name. Save, refresh the browser. 
    <header>
  <h1>Your name</h1>
</header>
    You should see your name.
  5. Inside the header, below the <h1>, add a <nav> with three links. Save, refresh. 
    <nav>
  <a href="#about">About</a>
  <a href="#projects">Projects</a>
  <a href="#contact">Contact</a>
</nav>
    You should see three links under your name.
  6. After the header, add <main> containing one <section id="about"> with an <h2>About</h2> and a paragraph about you. Save, refresh. 
    <main>
  <section id="about">
    <h2>About</h2>
    <p>A paragraph about you.</p>
  </section>
</main>
    You should see the About block under your nav.
  7. Still inside <main>, add a <section id="projects"> with an <h2>Projects</h2> and two <article>s, each holding an <h3> project name and a one-line description (freeCodeCamp projects count). Save, refresh. 
    <section id="projects">
  <h2>Projects</h2>
  <article><h3>Project name</h3><p>One-line description.</p></article>
  <article><h3>Another project</h3><p>One-line description.</p></article>
</section>
    You should see both project blocks below About.
  8. Close the page with a <footer id="contact"> containing your email or GitHub link. Save, refresh. 
    <footer id="contact">
  Your email or GitHub link
</footer>
    Success check: clicking each nav link scrolls/jumps to its section.
  9. Audit it — in Chrome or Chromium (Lighthouse ships in Chromium-based browsers; Firefox doesn't have it — if Firefox is your daily browser, open the page in Chromium just for audits): press F12 → find the Lighthouse tab (it may hide behind ») → check only Accessibility → Analyze. You should see a score. Read the top suggestion — fix it if it's one you understand, ask your teacher if not.

Check yourself — fix the snippet

This page fragment renders fine but fails semantics review. Find all three problems before revealing:

<div class="header"><h1>Salma's Recipes</h1></div>
<main>
  <section><h2>Latest</h2>...</section>
</main>
<main>
  <section><h2>Popular</h2>...</section>
</main>
<div class="footer">© 2026</div>
Reveal the three problems
  1. <div class="header"> should be <header> — a div announces nothing to assistive tech.
  2. Two <main> elements — a page gets exactly one; merge the sections into it.
  3. <div class="footer"> should be <footer>.

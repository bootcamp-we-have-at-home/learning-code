2-9 — Traffic Lights: Callbacks Morning Challenge

~60 minutes · Week 2, Day 3 (09:00–10:00 morning challenge) · Source: curriculum bootcamp-we-have-at-home/morning-challenge-traffic-lights

Why this matters: this is the bridge between the toy setTimeout chains you predicted in lesson 2-7 and week 3's real async work — here a callback chain drives something you can watch, so "the callback runs later" stops being a rule you memorised and becomes a light you can see turn on. Week 3 opens by asking "what is a callback and why would you use one?"; after this hour you answer it with a working animation.

Idea 1 — A function that hands you the "when I'm done" slot

The challenge repo ships a helper you must not edit, blinkLight. It's a function that builds and returns another function — first-class functions, exactly as lesson 2-1 defined them (functions are values: you can store them, pass them, and return them). Read it once; you only ever use it:

// this block ships in script.js — read it, don't edit it
var time = 1000;                                  // every blink lasts 1 second

var red    = blinkLight(get('light-top'),    'red');     // red, yellow, green are FUNCTIONS
var yellow = blinkLight(get('light-middle'), 'yellow');  // built once, called many times
var green  = blinkLight(get('light-bottom'), 'green');

var red2    = blinkLight(get('light-top2'),    'red');   // the SECOND traffic light,
var yellow2 = blinkLight(get('light-middle2'), 'yellow');// already built for you —
var green2  = blinkLight(get('light-bottom2'), 'green'); // you only need these in Part 4

function blinkLight(element, colour) {
  var blink = function (callback) {
    element.classList.add(colour);                // light ON  (the DOM class trick from 1-10)
    setTimeout(function () {                      // the timer from 2-7
      element.classList.remove(colour);           // light OFF, one second later
      if (callback) {
        callback();                               // ...then run whatever you passed in
      }
    }, time);
  };
  return blink;                                   // returns a function, not a colour
}

function get(id) {                                // a one-line alias for the 1-10 DOM lookup
  return document.getElementById(id);
}

So red is not a value, it's a function you call. red() means "red on for a second, then off, then nothing". red(green) means "red on for a second, then off, then run green" — green passed without parentheses, because you're handing over the function itself, not its result (2-1's most-repeated warning).

The repo writes var and function (callback) { … }; today we write const and arrow functions. Leave the shipped block exactly as it is — it's the "don't change anything between here / and here" zone — and write your own code below it in modern style.
More examples (optional)

The same shape, stripped of traffic lights — a function whose one job is to do something and then call your function:

const after = (label) => (callback) => {          // build a "step" function
  console.log(label);
  setTimeout(callback, 1000);                     // ...then run the callback a second later
};

const first  = after("first");
const second = after("second");

first(second)          // logs "first", waits 1s, logs "second"
first()                // logs "first", waits 1s, does nothing — no callback passed
first(second)          // NOTE: second, no parentheses. first(second()) would run it NOW

And the mistake worth making once on purpose, so you recognise it in your own code tonight:

red(green())    // WRONG: green() runs immediately, and its return value (undefined)
                //        is what red receives — so nothing happens after red
red(green)      // RIGHT: red receives the function and calls it when it's done

Read more: MDN — Element.classList · javascript.info — closures (why the returned blink still remembers its element and colour)

Idea 2 — Chaining, and the anonymous-wrapper trick

Two lights in a row is easy: red(green). Three is where beginners stall, because the obvious guess is wrong:

red(green, yellow)          // WRONG: blinkLight takes ONE callback; the second is ignored
red(green(yellow))          // WRONG: green runs immediately (see Idea 1)

The fix is the takeaway of this whole challenge: when the next step needs an argument of its own, wrap it in an anonymous function. That wrapper is a function value, so it can be passed; and its body doesn't run until it's called:

red(() => green(yellow))    // red → (1s) → green → (1s) → yellow

Read it inside-out: () => green(yellow) is a function that, when someone calls it, starts green with yellow queued behind it. red is that someone, one second later. Longer chains nest the same way — and yes, the parentheses pile up on the right. That pyramid has a name you'll meet in week 3 ("callback hell") and a cure you'll meet there too (promises, async/await); for one hour, embrace it.

Two lights at the same time is a different move, and you need it below for the red-and-yellow stage: you don't nest, you call both in one tick and let only one of them carry the chain onward:

const bothThenGreen = () => {
  red();               // starts now, no callback — this one just lights up and stops
  yellow(green);       // starts now too, and carries the sequence onward after 1s
};

Both classes get added in the same tick, so the browser paints them together: one second of red-and-yellow, then green. Which of the two carries the callback doesn't matter — what matters is that only one does, or you'd fork the sequence into two chains running side by side.

More examples (optional)

Four steps, built up one at a time so the nesting never surprises you:

red(green)                                  // 2 steps
red(() => green(yellow))                    // 3 steps: wrap step 2
red(() => green(() => yellow(red)))         // 4 steps: wrap step 2 AND step 3

And the wrapper is not magic — it is the same thing as naming the step, which is often more readable once a chain gets long:

const thenYellow = () => green(yellow);     // a named function value...
red(thenYellow)                             // ...passed exactly like the anonymous one

Read more: callbackhell.com (the pyramid, and why week 3 escapes it) · javascript.info — setTimeout and setInterval

Do it for real (~45 min)

Four parts, exactly as the challenge repo states them. Parts 1–3 are the challenge; Part 4 is a clearly-marked stretch goal — a good morning if you finish Part 3. All your work happens in one file, script.js, below the shipped block.

Scroll to the bottom, past // --- AND HERE.. Delete the two example functions (light and light2 and the two calls under them); everything you write goes here.     // your code starts here
const light = () => {
  green(red);         // temporary: green, then red
};
light();
    Success check: on save the tab reloads and you see green for a second, then red for a second, then nothing.
  4. Part 1 — the cycle. Extend light so the first traffic light runs the full sequence, once: 
    // green → yellow → red → red & yellow → green
    Use the wrapper trick from Idea 2 for every step that needs an argument, and Idea 2's bothThenGreen shape (call two lights in one tick, only one carries the callback) for the red-and-yellow stage. You should see all five stages in order, ending on a green blink, then the lights stay off.
    Stuck for more than 10 minutes? One way to do Part 1 
    const light = () => {
  green(() => yellow(() => red(() => {
    red();            // red and yellow together...
    yellow(green);    // ...yellow carries the chain to green
  })));
};
light();
  5. Part 2 — red holds for 3 seconds, with the rest of the sequence unchanged. time lives in the do-not-edit block, so instead make red blink three times back-to-back — red(() => red(() => red(next))) — and give that shape a name so light stays readable: 
    const redFor3 = (next) => red(() => red(() => red(next)));   // 1s + 1s + 1s
    Slot redFor3 into your Part 1 chain in place of the single red. You should see red stay lit for three solid seconds — no flicker between the blinks, because each remove and the next add happen in the same tick, before the browser gets a chance to paint (2-7's event loop, visible to the naked eye). The other four stages still last one second each, in the same order.
  6. Part 3 — loop forever. Make the first light cycle continuously by having light end by scheduling itself: recursion, the same idea as any recursive function you wrote for your degree, except the recursive call happens from inside a callback rather than immediately. The last stage's callback is where it goes. 
    // the final callback in the chain becomes: light
// (the function itself, no parentheses — same rule as everywhere else today)
    Success check: the light runs green → yellow → red (3s) → red&yellow → green → yellow → … and never stops. Leave it running a full minute to be sure it never drifts or double-fires.
  7. Part 4 — stretch, clearly optional. The HTML ships a second traffic light (red2, yellow2, green2 are already built for you in the shipped block). Write a light2 that loops alongside light, obeying the repo's rules: green only while light 1 is red; yellow while light 1 is transitioning green→red; red while light 1 is green or yellow; red&yellow while light 1 transitions back to green. Start both loops in the same tick: 
    light();
light2();             // both chains start together and stay in step
    Since light 1's cycle is 1 + 1 + 3 + 1 = 6 seconds, light 2's must be too — work out its four stages so the seconds line up. Success check: the two lights never show green at the same time, and the pair matches the demo GIF in the challenge README.
  8. Stop the server when you're done: click the terminal running npm run live and press Ctrl+C. You should see your shell prompt return, and the browser tab stop reloading.

Check yourself — predict the output

All three timers are started in the same tick. Write down the exact order of the five lines before you paste this into the F12 console (lesson 1-1):

console.log("A");
setTimeout(() => console.log("B"), 100);
setTimeout(() => console.log("C"), 0);
setTimeout(() => console.log("D"), 50);
console.log("E");
Reveal

A, E, C, D, B.

The two console.logs are synchronous, so they run first, in source order — A then E. The three callbacks were merely scheduled; each fires when its own delay expires, counted from the moment it was registered. All three were registered in the same tick, so they come back sorted by delay: 0, 50, 100. Source order decides nothing once a timer is involved — which is exactly why your traffic light has to chain callbacks instead of writing the five stages one after another.

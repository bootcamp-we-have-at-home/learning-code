Node & npm setup

CommandWhat it does
node -vprints the installed Node version — no output / "command not found" means Node isn't installed
npm -vprints the npm version (npm ships with Node)
sudo pacman -S nodejs npminstall both on Arch Linux (other distros / nvm differ)
nodeopens the Node REPL — prompt is >, type JS, exit with .exit or Ctrl-D
node file.jsruns a JavaScript file outside the browser
npm init -ycreates package.json accepting all defaults (drop -y to answer prompts)

package.json is the project's ID card: its name and version, its scripts, and the list of packages it depends on. It is committed to git.

Installing packages

CommandWhat it does
npm install <pkg>install a package the finished program needs (dependencies)
npm install -D <pkg>install a dev-only package — testing tools, build tools (devDependencies). -D = --save-dev
npm installwith no package name: reads package.json and downloads everything it lists — what you run after cloning a project (clone: lesson 1-5)
npm uninstall <pkg>remove it and drop it from package.json

node_modules/ is generated, huge, and never committed — put it in .gitignore. package-lock.json records the exact versions installed and is committed.

npm scripts

"scripts": {
  "test": "jest",              // npm test
  "start": "node index.js"     // npm start
}
CommandWhat it does
npm testruns the test script (built-in shortcut; start too)
npm run <name>runs any other script by name
npm runlists the scripts this project defines

Why scripts work when typing jest in the shell doesn't: npm puts node_modules/.bin on the PATH while a script runs, so locally-installed tools are found without a global install.

Jest

const add = require("./add");        // import the function under test

test("adds two numbers", () => {     // name answers "what should it do?"
  expect(add(2, 2)).toBe(4);         // actual, then the matcher, then expected
});
MatcherPasses whenUse for
expect(x).toBe(y)x === y — same value or the same objectnumbers, strings, booleans
expect(x).toEqual(y)contents match, walked deeplyarrays, objects — two separately-built objects are never === (reference comparison, lesson 1-7)
expect(x).toBeNull()x is literally null"deliberately nothing" return values
expect(fn).toThrow()calling fn throws an errorerror paths (full matcher list)
RunningWhat it does
npm testruns every test file once
npm test -- --watchwatch mode: reruns on save. The bare -- passes the flag through to Jest. Quit with q
npm test -- addruns only test files whose path matches "add"

Jest finds tests by name — any *.test.js file, or anything inside a __tests__/ folder. No config needed.

Failure shapes worth recognizing: Cannot find module './add' = the file or its export is missing; Expected: … / Received: … = the file loaded and the logic is wrong.

module.exports / require

A function must leave its file before a test can call it. Node's built-in pairing:

// add.js — the implementation
const add = (a, b) => a + b;
module.exports = add;                    // export one thing

// add.test.js — the test
const add = require("./add");            // "./" means "file next to me"; .js optional
// exporting several functions from one file
module.exports = { add, subtract };

// and unpacking them on the other side
const { add, subtract } = require("./maths");

TDD

BeatDo
RedWrite one failing test and run it — seeing it fail proves it can
GreenWrite the simplest code that makes it pass. Nothing extra
RefactorTidy the code with the tests green; rerun after every change

Ping-pong pairing: A writes a failing test, B makes it pass and writes the next failing test, swap — repeat.

Coverage: npx jest --coverage reports which lines your tests actually executed (Jest uses Istanbul under the hood; nyc is Istanbul's standalone command-line tool). 100% coverage means every line ran, not that every behavior is correct.

Call stack & async (week 2)

Call stack: JavaScript keeps a stack of "who called whom" — each call is pushed on, and pops off when it returns, so the innermost call finishes first. Endless recursion overflows it: RangeError: Maximum call stack size exceeded.

IdeaMeaning
synchronouseach line finishes before the next starts — JavaScript's default
asynchronousthe work is handed off (timer, network) and your code continues; your callback runs later
setTimeout(fn, ms)run fn after at least ms milliseconds; returns a timer id, not fn's result
setTimeout(fn, 0)still after all the currently running synchronous code — 0 means "as soon as the stack is empty", not "now"
nesting callbacksto go more than one layer deep, wrap in an anonymous function: third(() => second(first)), never third(second(first))
const asyncAddOne = (n, callback) => {
  setTimeout(() => callback(n + 1), 1000);   // returns undefined immediately; callback runs later
};
asyncAddOne(10, (result) => console.log(result));   // 11, one second later

Web storage

CallDoes
localStorage.setItem("key", "value")saves a string, surviving reloads and browser restarts
localStorage.getItem("key")returns the string, or null if the key was never set
localStorage.removeItem("key")deletes one key (localStorage.clear() wipes the whole origin)
sessionStorageidentical API, but cleared when the tab closes

Storage only holds strings, so objects and arrays make a JSON round trip:

localStorage.setItem("cart", JSON.stringify(cart));            // object → string
const cart = JSON.parse(localStorage.getItem("cart")) || [];    // string → object; || [] covers the first visit

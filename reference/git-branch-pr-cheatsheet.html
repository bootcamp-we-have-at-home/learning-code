Git Branch & PR Workflow

The loop you'll run on every feature, forever.

The cycle

git switch main
git pull                      # start from the latest main
git switch -c feat/short-name # new branch per unit of work
# ...edit files...
git add -p                    # stage hunk by hunk, review as you go
git commit -m "Add X so that Y"
git push -u origin feat/short-name
# open PR on GitHub → review → merge
git switch main && git pull   # sync, then delete the branch
git branch -d feat/short-name

Getting an existing repo (lesson 1-5)

git clone https://github.com/OWNER/REPO.git   # creates a folder named REPO here; cd into it next

Commands by intent

I want to…Command
See what state I'm ingit status
Start a new piece of workgit switch -c feat/name
Review before staginggit diff / git add -p
Review what's stagedgit diff --staged
Undo unstaged file changesgit restore file
Unstage a filegit restore --staged file
See branch historygit log --oneline --graph --all
Publish branch first timegit push -u origin branch
Update branch with maingit switch main; git pull; git switch -; git merge main

Merge conflicts (lesson 1-9)

git merge main            # CONFLICT (content): … — git wrote BOTH versions into the file
git status                # lists the files under "Unmerged paths"
# edit each file: keep the text that should survive, delete the
# <<<<<<< HEAD / ======= / >>>>>>> marker lines
git add FILE              # marks the file as decided
git commit                # concludes the merge
git merge --abort         # escape hatch: rewind to before the merge, any time before committing

Commit message rule

Imperative mood, says why not just what: Add validation so empty forms can't submit — not fixed stuff.

Glossary

TermMeaning
branchA movable pointer to a commit; a parallel line of work
mainThe shared, always-working branch; never commit to it directly
remote / originThe copy of the repo on GitHub
pull request (PR)A request to merge your branch, with a diff others can review
mergeCombine one branch's commits into another
staging areaThe set of changes queued for the next commit
merge conflictBoth branches changed the same lines; git writes both versions into the file and waits for you to choose
HEADThe commit you're currently standing on — in a conflict, the "yours" side of the markers
